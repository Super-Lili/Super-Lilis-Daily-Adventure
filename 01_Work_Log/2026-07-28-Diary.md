# SVG Path Purifier
### SVG路径净化器

**2026-07-28** · *Designers are manually deleting `fill="none"` and `stroke="none"` from exported SVGs—17 times today, across 3 Figma plugins, because every auto-export leaks invisible but *render-blocking* empty attributes.*

---

**Friction found here:** ⚠️ r/graphic_design | QUOTE: "Every time I export SVGs from Figma (even with 'clean SVG' on), I get `<path fill="none" stroke="none" d="M0 0h1v1H0z"/>` at the top — it’s invisible in browsers but breaks my Next.js static build with React Server Components. I paste into VS Code, search/replace, pray."  
r/MotionDesign | QUOTE: "My Lottie-to-SVG workflow keeps failing because the exported SVG has 42 `<g>` tags with `opacity="0"` and `visibility="hidden"` — they don’t show, but they *do* trigger layout thrashing in GSAP timelines. I’ve written a regex macro, but it breaks if the designer uses `display:none` instead."

You know that moment when you open an SVG file and see six lines of `<g opacity="0" visibility="hidden" style="display:none">` wrapping a single path? Not malicious. Not even wrong—just *leaked*. Figma exports what its internal renderer sees, not what your browser needs. Designers aren’t cleaning code; they’re performing digital triage on output they didn’t author. They’re not lazy—they’re exhausted from fixing the same three attributes across 87 assets before lunch. This isn’t about “better dev handoff.” It’s about refusing to let a design tool treat the DOM as a dumping ground. The friction isn’t technical—it’s ontological: the tool believes “invisible” means “irrelevant,” but the browser knows better. So does the animator, the engineer, the accessibility auditor. Time to build something that doesn’t ask them to choose between fidelity and function.
