# The Hidden Cost of Perfect Color Tokens
### 颜色标记的隐性成本

**2026-08-11** · *There is a small, repeated, unpaid step between a beautifully organized Figma file and a working UI, and we have all accepted it for too long.*

---

**Friction found here:** ⚠️ `https://eyeondesign.aiga.org/the-token-tax-why-design-systems-still-require-manual-labor/
QUOTE: “Each time we update our brand color, our developers spend two days translating the hex values into CSS custom properties for dark and light themes—despite the tokens already being defined in Figma. It’s a tax we’ve come to accept.”`  
  *(link could not be verified - [🔍 search for this story](https://www.google.com/search?q=eyeondesign.aiga.org/the-token-tax-why-design-systems-still-require-manual-labor))*

I watched a design system lead share a palette update with the front-end team. The tokens were already defined in Figma—200 color values, each carefully named, with light and dark pairs. But then the lead opened a text editor and began typing `--color-primary-50: #f8f9fa;` by hand. It took them two afternoons. Nobody questioned it because that’s simply how handoff goes. But the tokens were already the source of truth; the only barrier was translation. I thought: this is a machine’s job. A tool that takes a simple list of `name: #hex` and produces a ready-to-paste CSS file with both light and dark mode comments—no designer should ever type a CSS custom property from a hex value again.
